Quick start for any GitHub user

  1. Install Git and uv.
  2. Clone the repository.
  3. Set HF_TOKEN (preferred) or HUGGING_FACE_HUB_TOKEN in your user environment when private or gated Hub content is needed.
  4. Run launch.cmd on Windows 11 or ./launch.sh on Linux.
  5. Use the pages from left to right.

The UI is available only on this computer at 127.0.0.1. Ollama is an optional post-training test target, not a trainer. Use the confirmed Stop app sidebar control to cancel active jobs, stop verified app-owned workers, and close the local server without stopping Ollama.

Choosing a technique

  • LoRA: train small adapters with normal model weights.
  • QLoRA: quantize the base model to reduce VRAM while training LoRA adapters.
  • OFT/QOFT: orthogonal fine-tuning adapters; QOFT uses the same 4-bit base as QLoRA.
  • Full: update every weight; use only when the preflight memory and disk gates pass.
  • SFT/CPT: learn examples or continue language-model training.
  • DPO/ORPO/SimPO/KTO/reward/PPO/GRPO: alignment recipes requiring their documented canonical columns. PPO cannot resume from a checkpoint.

Technical and code guide

app.py owns Streamlit UI and creates a schema-v5 RunManifest with a list of dataset sources. jobs.py persists status and launches an isolated worker. worker.py performs preflight, multi-dataset concatenation, recipe dispatch, evaluation, checkpoints, and export. storage.py owns migrations, integrity checks, backup, and restore. runtimes.py provisions locked hardware profiles. SQLite is a status projection; manifests, JSONL events, logs, checkpoints, and hashed artifacts are the durable run record.

UI → validate manifest → SQLite/job directory → preflight
   → Transformers/PEFT/TRL or compatible Unsloth
   → evaluation → adapter/merged export → optional Hub/Ollama

Use uv run pytest, uv run ruff check ., uv run ty check, and uv build before contributing. Releases are built from tags into wheel, source distribution, checksums, SBOM, and GitHub provenance.

Business guide

The product reduces command-line setup and records reproducible provenance for local experiments. It does not make a model safe, accurate, licensed, or production-ready automatically. Budget for dataset rights, human evaluation, red-team testing, hardware time, storage, and deployment monitoring. Keep private datasets local and review every model license before distribution.

Operations and recovery

fine-tuning-studio doctor --json
fine-tuning-studio backup
fine-tuning-studio restore PATH

Upgrades create a consistent database and manifest backup before migration. A failed migration rolls back; restore only while no jobs are active. Never share diagnostic files until reviewing paths and model identifiers.
